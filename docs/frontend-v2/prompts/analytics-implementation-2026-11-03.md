### Общий период, запросы и состояния

- Общие организация и применённый период для всех вкладок. Пресеты 7/30/90,
  произвольный период и один день; включительные календарные даты в timezone
  организации, максимум 366 дней. Проверяй неполный/невалидный диапазон и
  `from > to`. Не запрещай будущие даты, если контракт их допускает.
- Разделяй draft и applied. Отмена, крестик и Escape не меняют применённый
  период. Редактирование работает из любого выбранного диапазона, а не только
  из стартовых 7/30 дней в Figma. На mobile диалог полноэкранный; реализуй
  focus trap, доступные ошибки, клавиатуру, закрытие и возврат фокуса.
- Смена периода согласованно обновляет данные и сбрасывает cursor журнала.
  Переключение вкладок/возврат сохраняют период. Сохраняй совместимость URL
  и нужные query-параметры; существующий rangeToQuery не должен терять вкладку.
- `/api/v1/analytics/summary` — общий источник сводки, рядов, счётчиков и
  итогов оплат; `/api/v1/analytics/payments` — cursor-журнал;
  `/api/v1/risks/precision` — качество. Это независимые query families, а не
  отдельный запрос на каждую карточку. Не выдумывай отсутствующие endpoints.
- Для precision переводи даты в UTC-интервал с исключительной верхней
  границей существующим timezone-helper. Учти переход DST.
- Query keys включают организацию и период; запросы отменяются либо поздние
  ответы игнорируются. После смены организации/периода старые данные не должны
  отображаться под новым контекстом. Соблюдай действующие permission gates.
- Реализуй loading, empty, success, refetch, error и local retry по карте.
  Loading не изображай нулевыми данными. Ошибка summary затрагивает его блоки,
  но не скрывает независимый доступный журнал/precision. Не добавляй новый
  stale-error режим вместо утверждённого error-состояния. 401/403 и недоступная
  организация 404 не являются пустой аналитикой.
- Числа одной организации/периода согласованы между вкладками. Копии NO/NR
  и risk/conversation в Figma используют отдельные иллюстративные fixtures;
  их различающиеся суммы/lifecycle не копируй в реализацию. API не обещает
  атомарного snapshot между тремя endpoints.

### Обзор

Реализуй KPI, атрибуцию, активность, график и «Данные по дням» из загруженного
`summary.series`, без нового endpoint. Отличай confirmedRecovered от всех
подтверждённых оплат и от оценочной воронки/paid outcome. Не смешивай отсутствие
активности, отсутствие оплат, organic при recovered=0, неизвестную атрибуцию
и неизвестную оценку. Сохрани нулевые дни, выбранный день, работу таблицы на
7/90 днях, длинные подписи и большие суммы. График/таблица должны работать
с клавиатурой и touch без обязательного hover.

### Риски и качество

Сводка событий и precision загружаются/повторяются независимо. Покажи шесть
канонических типов в установленном порядке. События за период и cohort с
последним feedback — разные основания: поздний TP→FP меняет precision,
но не превращает исторический счётчик событий FP в ту же метрику.

Утверждено: общий KPI `ΣTP/(ΣTP+ΣFP)`, не среднее процентов типов; подпись
«С действием» — «По дате действия». При нулевом знаменателе показывай
неизвестное значение/отсутствие feedback, а не выдуманные 0%. Используй
`minimumCoverage`/`reliable` из API; не фиксируй демонстрационный порог 50%.
Учти no-feedback, no-events, одну оценку, смешанные TP/FP и границы coverage.

### Оплаты

- Покажи оба итога за весь период и журнал подтверждённых положительных
  событий. Decimal string форматируй без потери денежной точности. Строка
  сохраняет исходную валюту, итоги — валюту организации по контракту.
  FX-only журнал может быть непустым при нулевых итогах в валюте организации.
- Сохрани fallback для nullable клиента/услуги, сортировку
  `confirmedAt desc / id desc` и timezone организации. Не добавляй PII-поля,
  редактирование/удаление/возвраты, новую оплату или новые статусы.
  Recovered revenue не означает возврат денег; unknown attribution не ошибка.
- Пагинация только по `nextCursor`, без номеров страниц и неизвестного total.
  `nextCursor=null` убирает «Показать ещё». Текущий page size 20 не меняй ради
  демонстрации 4→8→9 строк в Figma.
- При fetchNextPage и его ошибке сохраняй строки и scroll; local retry
  повторяет нужную страницу. Добавляй события без дублей по eventId. Отличай
  initial error от next-page error: текущая проверка `payments.isError`
  не должна скрывать уже загруженный журнал.
- Известная ошибка недействительного continuation `400 INVALID_ARGUMENT`
  предлагает «Обновить список» и загружает первую страницу со сбросом к началу
  журнала. Не трактуй любой HTTP 400 как эту ошибку.
- Ссылки в существующие риск/диалог определяются `riskId`/`conversationId`
  и правами, не одной атрибуцией. Возврат сохраняет вкладку, период, страницы,
  anchor/scroll и фокус. При смене организации/прав не восстанавливай чужой
  кеш. Недоступный объект/изменённые права обрабатывай текущими recovery patterns.
