# Запуск Codex для frontend v2

Точка входа — корневой [AGENTS.md](../../AGENTS.md). Модели и роли:
[CODEX-OPERATING-RULES](CODEX-OPERATING-RULES.md), проектный `.codex/config.toml`
и пять `.codex/agents/*.toml`. Claude-конфигурация сохраняется отдельно.

## В приложении

Открой существующий проект `Lidradar-front` с текущей рабочей копией и передай
поручение из [CODEX-START](CODEX-START.md). Выбери `gpt-6.1-sol`, effort medium.
Текущий чат может сохранить ранее выбранную модель. Новые конфигурации ролей
могут потребовать новой сессии; не создавай чистый worktree вместо dirty tree.
Проверь фактическое обнаружение ролей и доступ к изображениям/Figma перед UI QA.

Если среда предоставляет только универсальный инструмент субагентов, ведущий
передаёт инструкции TOML и модель/effort явно. Название роли в тексте само по себе
не доказывает применение настроек. Независимым задачам передаётся короткий
[brief](CODEX-TASK-BRIEF.md), а не вся история чата.

## В терминале

```sh
cd /Users/aleksandrkisler/Develop/LidradarWorksapce/Lidradar-front
bash scripts/codex-frontend.sh doctor
bash scripts/codex-frontend.sh start
```

`doctor` — режим по умолчанию; он проверяет Node из `.nvmrc`, наличие CLI и
startup config, выводит конфигурации моделей/ролей. Он не запускает LLM-задачу,
не исправляет frontend и не доказывает реальное использование ролей.
При необходимости укажи полный путь к CLI в `LIDRADAR_CODEX_BIN`.

Если CLI не авторизован, отдельно выполни `bash scripts/codex-frontend.sh login`.
Это штатный вход Codex через браузер; токены/коды в чат передавать не нужно.
Login не требует Node, backend docs или дизайн-пакета.
`bash scripts/codex-frontend.sh resume` открывает выбор существующей сессии.
Не выбирай автоматически последний чужой чат и не запускай Claude одновременно
на тех же файлах.

Launcher использует workspace-write и on-request, сохраняет штатную проверку
разрешений. При первом запуске может потребоваться доверие каталогу, чтобы Codex
загрузил project config. Глобальные настройки, auth и provider не меняются.
Внешние источники читаются по SOURCES; launcher не добавляет их через `--add-dir`,
который разрешил бы запись. Если sandbox ограничивает чтение, разрешение нужно
только для нужного источника; независимая локальная работа продолжается.

Figma использует существующий подключённый плагин/MCP родительской сессии.
Этот пакет не переносит `.mcp.json` Claude и OAuth между клиентами.
При недоступном Figma используй сохранённые exports с source-map/hash;
без нужного читаемого эталона соответствующий UI результат — UNVERIFIED.

Обычный цикл: разработчик → QA TEST/FUNCTIONAL → UI desktop/tablet/mobile.
Worker и explorer подключаются для независимых задач; Astra — только явная
консультация. Смена исполнителя не отменяет текущие AC, финальные gates и
исторический R1 FAIL. Следующий старт — сверка checkpoint и открытых findings,
а не повторная реализация регистрации.

Формат проверен по [OpenAI Docs](https://learn.chatgpt.com/docs/agent-configuration/subagents)
и установленному CLI `0.165.0-alpha.1.2` от 29.10.2026. Проверка загрузки ролей
в LLM-сессии и фактическая независимая приёмка остаются отдельными runtime-шагами.
