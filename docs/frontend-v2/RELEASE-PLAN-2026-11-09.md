## HF-ONB-01 · Удаление точек и услуг при первичной настройке

Затронуты US-M02-02/03/04. Регрессии: US-M02-01 (одна компания), каталог M03.
Роль — владелец. Область — первичная настройка чистого рабочего пространства,
в котором ещё нет аналитики, статистики и рисков. Сохраняется согласованное
поэтапное сохранение данных в рамках одной компании.

| Сценарий                                                                             | Ожидаемое поведение                                                                                             |
| ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| На шаге 2 удаляют точку без привязанных услуг                                        | Точка удаляется из настройки                                                                                    |
| На шаге 3 удаляют ненужную услугу                                                    | Услуга удаляется из каталога; точка и остальные услуги сохраняются                                              |
| На шаге 3 создали услугу с привязкой к точке, вернулись на шаг 2 и удаляют эту точку | До удаления открывается предупреждение: связанные услуги сохранятся и будут действовать во всех точках компании |
| Отменяют удаление в предупреждении                                                   | Точка и прежние привязки услуг сохраняются                                                                      |
| Подтверждают удаление точки                                                          | Точка удаляется, привязанные к ней услуги получают область «Все точки»; их названия и цены сохраняются          |

Предлагаемый текст для будущего согласования макетов:

> **Удалить точку «Центральная»?**
>
> К этой точке привязаны 3 услуги. После удаления точки они будут действовать
> во всех точках компании.
>
> Действия: «Отмена» и «Удалить точку». Показать затронутые услуги.

Название точки и число услуг в примере заменяются фактическими значениями.

## Критерии будущей приёмки

1. Доступны удаление точки на шаге 2 и удаление услуги на шаге 3.
2. Связанные услуги переводятся на «Все точки» только после подтверждения
   предупреждения; отмена сохраняет исходное состояние.
3. Услуги других точек и уже общие услуги не изменяются.
4. После возврата на шаг 3 и перезагрузки сохраняется подтверждённый результат.
5. ID компании остаётся прежним, операции не создают новую компанию.
6. После удаления последней точки шаг 2 снова незавершён; можно добавить нужную.
7. Успех показывается после подтверждения полного результата удаления и смены
   привязок. Ошибка и неизвестный исход не выдаются за успех; повтор не создаёт
   дубликаты и учитывает уже подтверждённые операции.

## Подготовка и ограничения

По [порядку изменения US](../USER-STORY-CHANGE-WORKFLOW.md) следующий этап —
макеты desktop/tablet/mobile и их согласование. Далее: обновление US → решение
и границы/API → backend при необходимости → frontend → TEST/FUNCTIONAL/UI
и регрессии. Поведение удаления в действующих пространствах отдельно не меняется.

Техническая семантика удаления, перенос привязок услуг и защита от частичного
результата требуют сверки с backend. Текущие операции деактивации сами по себе
не подтверждают поддержку нового сценария; новый API этим планом не объявляется.
Исправления остальных переходов и редактирования мастера в эту задачу отдельно
не включены; сохранность одной компании и возврат 3 → 2 → 3 нужны для её проверки.
