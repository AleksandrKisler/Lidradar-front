## Состав и поведение

Загрузка/ошибка summary и payments разделены. Обе итоговые карточки приходят
одним summary: отдельные ошибки карточек не выдуманы. Skeleton сохраняет
структуру и скрывает ещё не полученные значения. При новом периоде старые
наборы скрыты; новый ответ каждого источника показывается независимо.
Refetch error соответствует текущему frontend: ошибочный блок заменяется
локальным сообщением, доступный соседний блок сохраняется. Stale-режим не добавлен.

Пагинация: B00→LM1→LM2→LM3→LMEND, четыре→восемь→девять уникальных eventId.
LMERR локально повторяет следующую страницу; LMX предлагает «Обновить список»,
LMRESET перечитывает начало, RESETDONE возвращает к заголовку нового журнала.
Внутреннее слово «курсор» не попадает в интерфейс. nextCursor=null убирает
активную догрузку; количество означает загруженные записи, неизвестный total
и номера страниц не добавлены. Демоlimit4 допустимAPI1..100; текущий frontend
limit20 не менялся. Позиции первых четырёх записей совпадают во всех семи
проверенных вариантах догрузки/возврата на каждом адаптиве; footer pending/error
держит высоту100px на D/T и138px на M. Реальный browser scroll этим не доказан.

Итоги отражают полный выбранный период только в RUB организации. Все9:
73500,46₽, из них49500,05₽ после риска; сумма RUB первых4 —43500,50₽.
Пустой период отличается от recovered0 при оплатах и от FX с двумя USD/EUR
записями и нулевыми итогамиRUB. Каждая запись сохраняет исходную валюту,
конвертации/курса нет. Синтетика покрывает nullable имя/услугу/оба,
длинные значения,123456789,99₽,0,01₽ и одинаковое confirmedAt. Порядок:
confirmedAt desc / id desc; отображение в Europe/Moscow. RECOVERED-примеры
имеют riskId; P04 без riskId — ORGANIC. Это положительные подтверждённые события;
«возвращено» означает выручку после риска, не возврат денег клиенту.

Канонический переход связан с P05 в LM2/RETURN: Дмитрий Соколов,
полировка18500,05RUB → существующий риск/переписка → RETURN с30днями,
восемью записями и якорем P05. Ссылки зависят от ID и существующего права,
не только от attribution. Отдельная payment-detail, edit/delete/refund
или новый lifecycle не добавлены.

TRISK/TCONV — review-копии существующих назначений с «К оплатам». CNF/T403

## Ограничения и будущая реализация

- NO/NR используют прежние **независимые presentation fixtures** соседних вкладок
  только для сохранения периода. В NO денежные суммы отличаются от Payments.
  Общий snapshot этих вкладок не подтверждён; аннотация и оба reviewers
  фиксируют это как ограничение storyboard. Существующие области не изменялись.
- Данные TRISK/TCONV также иллюстрируют существующий UI, не буквальный
  lifecycle-снимок события P05. Согласованность реального связанного объекта
  проверяется при реализации, бизнес-модель не меняется.
- Нужны сохранение loaded pages при next-page error, локальный fetchNextPage retry
  и reset invalid continuation. Сегодня общий payments.isError скрывает журнал.
- Нужны binding существующего conversation route, origin context/период/pages/
  anchor/focus при возврате. Текущий back риска ведёт в Radar, диалога — в список.
- Ручной refresh из дизайна пока не привязан runtime. Нельзя закреплять
  manual-only: текущие запросы имеют focus/reconnect и tenant invalidation.
- More у независимых7/4/90 и обновлённого UPD не ведёт к чужому набору30дней.
  Прототип ограничен canonical paging4→8→9 и заранее выбранными ветками.
  Реальный ввод дат представлен canned frames.
- Figma Present предпринят через in-app browser: navigation timeout, пустой
  AXWebArea, screenshot unavailable. Native Mac заблокирован. Фактическое
  проигрывание, scroll/focus/keyboard/DOM/ARIA/AT, API и live browser matrix —
  **UNVERIFIED**. TEST/FUNCTIONAL/browser UI — **NOT RUN**; design review
  не присваивает им PASS.

Следующий шаг — согласование владельцем базового Desktop, состояний и
минимальной C-синхронизации. Реализация требует отдельного поручения.
