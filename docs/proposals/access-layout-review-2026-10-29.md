# Доступ · Новая раскладка слева

Дата: 29.10.2026. Статус: **представлено пользователю на просмотр**. Это новая организация существующих макетов; прежние области и согласования сохранены.

## Основная горизонталь

[Раздел в Figma](https://www.figma.com/design/jN8Hhzn6ObIAEi7FoY9kPu?node-id=802-6798), страница «01 · Доступ». Раздел расположен слева от исходных макетов: x=-14240, y=0.

Девять основных desktop-экранов 1440×1000 находятся на одной линии:

| Порядок | Экран                                                             | ID         |
| ------- | ----------------------------------------------------------------- | ---------- |
| 1       | Вход с двумя ссылками                                             | `802:6805` |
| 2       | Регистрация по приглашению, ввод кода                             | `802:6846` |
| 3.1     | Создать аккаунт: приглашение проверено                            | `802:6874` |
| 3.2     | Создать аккаунт: открытая регистрация                             | `802:6919` |
| 3.3     | Создать аккаунт: закрытая регистрация                             | `802:6964` |
| 4       | Восстановление пароля, запрос письма                              | `802:6977` |
| 5       | Недействительная ссылка сброса, действие «Запросить новую ссылку» | `802:7008` |
| 6       | Новый пароль                                                      | `802:7033` |
| 7       | Подтверждение почты                                               | `802:7073` |

Три варианта регистрации объединены общей группой «Создать аккаунт». Последние два экрана — новый пароль и подтверждение почты. «Запросить новую ссылку» представлен действием существующего экрана недействительной ссылки, а не новым самостоятельным экраном. Для почты использован существующий исходный кадр с недействительной ссылкой подтверждения; он отделён подписью сценария от сброса пароля.

## Состояния форм

[Отдельная область ниже](https://www.figma.com/design/jN8Hhzn6ObIAEi7FoY9kPu?node-id=802-6799), x=-14240, y=1520.

20 карточек шириной 512 px сгруппированы по семи сценариям: вход, приглашение, создание аккаунта, восстановление пароля, ссылка восстановления, новый пароль, подтверждение почты. Здесь нет повторов внешнего layout, блока о продукте и общего нижнего footer. Правовой текст внутри регистрационной формы сохранён.

- У входа во всех трёх состояниях сохранены обе ссылки нового сценария.
- В приглашении показаны введённый код, проверка и ошибка формата. Для первых двух использованы состояния UI Kit. Ошибка формата перенесена из прежней общей регистрации в отдельный шаг ввода приглашения.
- В состояниях создания аккаунта удалено старое поле кода. Заголовок и ссылка другого приглашения синхронизированы с новым вариантом; при отправке ссылка приглушена. При загрузке формы используется нейтральный текст загрузки вместо утверждения, что код уже проверен.
- Остальные карточки извлечены из существующих desktop-кадров ошибок, отправки и первоначальной загрузки.

Проверены 9 экранов на одной горизонтали без пересечений, 20 карточек без пересечений, отсутствие внешней оболочки в области состояний и отсутствие поля кода в состояниях создания аккаунта. Просмотрены снимки основной горизонтали и области состояний, включая снимок после синхронизации ссылок входа.

Исходные разделы `461:5453`, `773:6360` и `795:6739` сохранены. Новая раскладка пока не заменяет их: пользователь просил сначала попробовать слева. Реализация приложения и канонические US в этой работе не менялись. Согласование прежнего дизайна не означает автоматического согласования новой раскладки и уточнённых карточек состояний.
