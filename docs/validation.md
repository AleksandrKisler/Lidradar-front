## Что выявила проверка на стенде

- `dev-data` отказывался поднимать фикстуры на схеме `000022` — исправлено на стороне backend (константа `SchemaVersion`).
- `GET /api/v1/risks` возвращал `500` для любой учебной организации: все фикстурные риски имеют `source = MANUAL`, а доменная проверка знала только `RULE` и `HYBRID`. Исправлено в домене backend; Radar и лента после этого работают на реальных данных (см. скриншоты в отчёте о работе).
- Внутренние ошибки Risk API не попадали в журнал сервера — добавлено событие `risk.request.failed` с `trace_id`.
- Мобильный профиль axe отметил прокручиваемую таблицу участников без фокусируемого содержимого (когда все кнопки отключены защитой последнего владельца) — область получила `tabindex` и имя.
- Полный параллельный прогон Playwright вскрыл гонку в диалоге подключения источника: две отправки в окне асинхронной проверки формы (двойной клик, клик и Enter) создавали два подключения. Исправлено синхронным замком отправки и состоянием занятости кнопки на время проверки; добавлен unit-тест.

## Известные ограничения инкремента

- Реализованы Radar, карточка риска с командами, действиями, исходами, вердиктом и подтверждением оплаты, realtime-обновления по SSE, диалоги только для чтения, онбординг с возобновлением по серверному статусу, настройки компании, точек, графика и услуг, интеграции источников, уведомления с личной привязкой Telegram, команда с одноразовыми кодами приглашений; смена этапа сделки, аналитика, приватность и админка — следующие блоки.
- Автопроверка привязки Telegram ограничена: раз в 5 с, только на видимой вкладке, не более 24 попыток на одну ссылку; дальше — ручная проверка или новая ссылка. Идентификаторы Telegram интерфейсу не передаются.
- Приглашения без писем: код показывается один раз и передаётся владельцем вручную; список приглашений кода не содержит. Защита последнего владельца на клиенте — подсказка, окончательное решение принимает сервер (`409 LAST_OWNER`).
- Отдельной ленты уведомлений внутри приложения нет: контракт её не отдаёт (GAP-API-013); переключатель «Внутри LidRadar» управляет доставкой на стороне сервера.
- В списке диалогов нет фильтров по точке и подключению в интерфейсе (параметры адреса принимаются): справочники точек и подключений появятся вместе с настройками и интеграциями.
- Контракт не отдаёт список вердиктов по риску: после перезагрузки панель оценки снова показывает форму, а записанный вердикт виден только по статусу `FALSE_POSITIVE`.
- История подтверждений оплаты в карточке ограничена итогом `confirmedRecovered` из read model: список событий выручки контракт не отдаёт.
- Полная история действий приходит из карточки в сокращённом виде (тип и время): заметки и автор в read model контракта отсутствуют.
- Лента обновляется по сигналам `/events`, при возврате фокуса, возврате сети и по кнопке; поток — ускоритель, время последнего снимка остаётся видимым.
- Внешняя ссылка в карточке показывается, только если её построил сервер; для каналов без deeplink выводится причина.
