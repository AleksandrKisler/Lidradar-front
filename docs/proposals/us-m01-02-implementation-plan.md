## Согласованное поведение

Общая ошибка над полями A/B в существующем `UiAlert tone=danger`:
**«Не удалось создать аккаунт»** и **«Проверьте данные или попробуйте позже.»**.
У email нет ошибки занятости; постоянная ссылка входа не зависит от ответа.
Для backend согласована замена `409 EMAIL_ALREADY_REGISTERED` на
`400 REGISTRATION_FAILED` без указания email/поля/причины в конверте.
Новый frontend принимает оба кода и показывает тот же блок; прежнее
раскрывающее описание в `messages.ts` также заменяется.

Это убирает явную подсказку из UI/API, но не делает результат регистрации
неразличимым: успех создаёт сессию, отказ — нет. Полная защита потребует
отдельного пути регистрации и макетов. Владелец проекта согласовал
новый ответ и это ограничение. `201`, тело регистрации и правила кодов
сохраняются; точный конверт и границы backend описаны в едином пакете.

## Состояния формы

| Событие                                       | Обязательное поведение                                                                                                                                   |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Отправка                                      | Один POST, `submitting`, повтор недоступен, значения сохранены                                                                                           |
| Новый или legacy-код отказа                   | Общий блок над полями, форма разблокирована; имя/email/скрытый пароль и проверенное приглашение B сохранены. Ошибка email из-за занятости не назначается |
| Редактирование после подтверждённого отказа   | Устаревший блок очищается, остальные значения и контекст B остаются. Запросов по вводу email нет, повтор только кнопкой/Enter                            |
| Исправленный адрес и повтор                   | POST с новым email и тем же ещё действующим кодом; ошибка формы не сбрасывает проверку. Окончательно код проверяет сервер                                |
| Недействительный код / смена сценария / выход | Очистка и переходы базового US-M01-01; сохранение формы не обходит отзыв или срок кода                                                                   |
| `429`                                         | Прежний Retry-After; изменение адреса не снимает ограничение                                                                                             |
| `201` + сбой `/auth/me`                       | Аккаунт уже создан; повторяется только загрузка сессии, не POST                                                                                          |
| Нет ответа / неразбираемый ответ / `5xx`      | Исход может быть неизвестен; сверка `/auth/me` по US-M01-01, без автоматического POST и без объявления, что аккаунт не создан                            |

После общего отказа фокус переносится в локальную программно фокусируемую
область сообщения после обновления DOM (`tabindex=-1` на обёртке).
`UiAlert` сохраняет `role=alert`. Email не выбирается как особое проблемное
поле. Локальные ошибки формата сохраняют `focusFirstProblem` и связь с полем.
Общий helper/все auth-формы ради этого отказа не меняются.

Пароль остаётся только в памяти текущей формы, не в storage/URL/telemetry.
Контекст B и 30-минутный TTL не продлеваются отказом; F5 и очистка — по
принятому базовому решению. Изменение поля не снимает 429 и блокировку
неизвестного исхода. При успехе письмо инициирует сервер на исправленный
адрес; frontend не дублирует письмо, онбординг не ждёт доставки.

## Границы будущего задания

| Файлы                                                                                                           | Изменение                                                                                                                                   |
| --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/features/auth-session/ui/RegisterForm.vue`                                                                 | Вместо ошибки занятости у email — одна общая ветка двух кодов, блок перед полями, сохранение значений и фокус                               |
| Модель потока из плана US-M01-01; `RegisterPage.vue` при необходимости                                          | Различить подтверждённый отказ, уже созданный аккаунт и неизвестный исход; сохранить проверенный B. Базовая модель ещё не реализована       |
| `src/shared/api/client/messages.ts`                                                                             | Одинаковые нейтральные подписи нового и legacy-кода. Server `message` не выводить; trace ID не добавлять третьей строкой этого бизнес-блока |
| Unit: register-form, invitation-registration, `tests/unit/shared/api-error.test.ts`; `tests/e2e/access.spec.ts` | Оба кода, место блока, отсутствие ошибки у email, значения/код, исправленный payload, число запросов, фокус и результат                     |
| `contracts/openapi.yaml`, `contracts/source.json`, `src/shared/api/generated/schema.d.ts`                       | Только штатная синхронизация после backend, без ручного редактирования                                                                      |

`src/entities/session/api/auth-api.ts` остаётся обычным POST без автоповторов
и новых методов. `UiAlert`, поля, session store, guards и маршрутизация
переиспользуются. Не расширять схемы входа/сброса пароля и общий helper фокуса.
Новые store, библиотеки, ENV и универсальная переделка auth не входят в объём.
