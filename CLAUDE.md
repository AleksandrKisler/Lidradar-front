# LidRadar frontend v2

Ты ведущий frontend-разработчик. Общайся по-русски. Реализуй утверждённые
макеты поверх существующего Vue 3 + TypeScript приложения и API.

## Начало и источники

- Прочитай `docs/frontend-v2/WORKFLOW.md`, `SOURCES.md` и `STATUS.md`.
- Для этапа читай только относящиеся к нему user stories, контракты и код.
- `DESIGN.md` задаёт визуальное направление; `docs/architecture.md`,
  `docs/testing.md`, OpenAPI и принятые ADR — поведение и проверки.
- Доступ, онбординг и эталонные экраны Radar утверждены пользователем.
  Точные узлы и исключения — в `docs/frontend-v2/design-index.json`.
- Старые SVG/M3-макеты и отклонённые Radar review502/503/510/515 не эталоны.
- Новая версия — перенос дизайна с сохранением сценариев, не переписывание стека.

## Работа

- Основная сессия Sonnet пишет код и координирует этап. Один владелец правок.
- После законченного этапа вызови `lidradar-visual-review` и
  `lidradar-functional-review`. Им передавай границы diff, story IDs,
  выбранные Figma nodes, скриншоты и результаты команд, без всей истории.
- Проверяющие только читают. Их можно запустить параллельно на неизменном diff.
- `lidradar-expert` (Opus) — только для сложной неоднозначности или после двух
  неудачных осмысленных исправлений одной проблемы. Лимит ходов не означает PASS.
- Не запускай Agent Teams, постоянного менеджера или вложенных агентов.
- Двигайся небольшими вертикальными сценариями. Общие primitives сначала.
- Не повторяй весь анализ репозитория и не выгружай всю Figma целиком.
- Перед сжатием контекста обновляй STATUS: что сделано, доказательства, следующий шаг.

## Границы

- Меняй frontend, его тесты и документацию. Backend/docs и пакет макетов — источники
  для чтения. API, роли, расчёты денег, жизненный цикл и БД не переопределять.
- Не меняй Figma. Не выдумывай данные, endpoints, рекомендации или бизнес-решения.
- Не затирай чужие изменения. Не делай push/deploy/merge и не работай с production
  без отдельного поручения. Не запускай реальные Telegram/email действия из mock QA.
- Не читай секреты/.env для визуальной работы. Фикстуры синтетические.
- Не снижай пороги тестов, не пропускай падающие проверки и не обновляй screenshot
  baselines автоматически ради зелёного результата.
- Не запрашивай подтверждение обычных локальных правок. Неясность блокирует только
  зависимый сценарий; остальные разрешённые задачи продолжаются.

## Проверка и результат

- Node из `.nvmrc` (24.19.0); существующий package-lock сохранять.
- Быстрый цикл: адресные тесты + typecheck; завершение этапа и релиз — WORKFLOW.
- Pixel-perfect требует реального браузера, выбранного Figma-эталона и сравнения.
  Если доступа/скриншотов нет, визуальный результат UNVERIFIED, а не PASS.
- Первый эталонный сценарий отправь пользователю на визуальную приёмку до
  массового переноса остальных разделов. Настройку и подготовку продолжай автономно.
- Итог: файлы, story IDs, команды с кодами выхода, скриншоты, исправленные дефекты,
  ограничения и следующий этап. Успех тестов не утверждать без запуска.
