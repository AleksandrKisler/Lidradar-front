   Сохрани типографику/порядок из frames и карточную phone-композицию.
2. **Редактор.** «Изменить» открывает отдельный редактор выбранного типа
   вместо прежнего inline details. Явное сохранение только одного riskType;
   clean не отправляется, изменение не вызывает autosave. Полное PUT тело
   по текущему контракту: IMMEDIATE/DIGEST/DISABLED, severity, inApp/Telegram,
   digestTime, quiet hours. Четыре порога важности; поля режимов/disabled —
   по кадрам. Значения скрытых полей не теряются из-за смены режима.
3. **Время.** `HH:mm` в поясе организации/настройки из API, без вывода города
   или фиктивного Europe/Moscow при неизвестном поясе. DIGEST требует валидного
   времени; quiet hours — обеих разных границ. Интервал через полночь допустим,
   start=end и неверный ввод не отправляются. Сохрани существующие defaults
   сервера и 24-часовой контрол; проверь 00:00, 23:59 и en-US.
4. **Сохранение/reset.** Saving блокирует повторную команду и конкурирующее
   закрытие. Error сохраняет ввод и позволяет осознанный повтор. Saved отражает
   подтверждённый ответ, а не локальную догадку; summary/происхождение обновляются.
   Reset — подтверждение, DELETE одного типа и перечитывание серверного default;
   никакого hardcoded сброса шести строк. Не смешивай отказ mutation и отказ
   последующего GET, не повторяй уже подтверждённую команду из-за read failure.
5. **Личный Telegram.** Подключение отделено от выбора канала в правиле.
   Выбрать Telegram без привязки можно, с пояснением. Issuing/pending/checking/
   expired/error и повтор новой ссылки — по кадрам и реальному ответу. TTL 15
   минут/`expiresAt`; проверка без Start не объявляет connected. Disconnect
   требует подтверждения, не меняет бизнес-источник переписки организации.
   Сохрани bounded polling/остановку при закрытии и смене user/tenant.
6. **Данные/черновики.** Initial loading/error отличаются от refresh-error:
   при неуспешном обновлении остаются подтверждённые данные и локальное сообщение.
   GET не стирает dirty ввод. При закрытии с изменениями должен быть явный путь
   продолжить редактирование или отказаться от изменений; не вводи autosave.
   При смене riskType/user/tenant drafts, ошибки, поздние ответы и Telegram token
   не перетекают в новый контекст. DISABLED не останавливает поиск рисков.

## Общие требования к реализации

Захватывай user/tenant/target ID и отправленное тело до await. Поздний ответ,
refetch, callback или возврат фокуса из прежнего контекста не меняет текущую
страницу и не адресует команду новой организации. Отдельно проверь tenant switch,
logout, удаление цели конкурентной сессией и повторное открытие диалога.

Timeout/обрыв после отправки не равен гарантированному отказу. Не показывай
ложный success и не делай слепой повтор POST выпуска приглашения. После
unknown POST код нельзя восстановить через GET: объясни неопределённый исход,
предложи перечитать список; новый выпуск — отдельное осознанное действие.
Для PUT/PATCH/DELETE сверяй доступное состояние и существующую семантику команды,
не добавляя новой серверной идемпотентности и не повторяя ACK-команды автоматически.

Сохрани существующую оболочку C и scoped изменения разделов. Shared расширения
только у ведущего, opt-in при изменении поведения. Учитывай регрессию замороженного
Доступа и принятых настроек; глобальные CSS/tokens ради одного экрана не менять.
Переиспользуй `UiSheet`/`UiDialog`, `UiSavedResult`, `UiTooltip`, `UiInput`,
`UiField`, кнопки/alerts и assets, когда они выражают нужный frame.

Диалоги: focus trap, начальный/возвращаемый focus, Tab/Shift+Tab, доступные имена,
