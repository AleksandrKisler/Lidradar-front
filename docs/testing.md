# Тестирование

## Наборы

- **Vitest + Vue Test Utils + jsdom**: переходы состояния риска, валидация env и данных API, ошибки HTTP, disabled-кнопка.
- **Playwright**: Chromium, Firefox, WebKit и мобильный WebKit; признание риска, Escape, восстановление фокуса, маршрутизация и отсутствие горизонтального переполнения.
- **axe-core** в Playwright: автоматические WCAG A/AA проверки основной страницы и диалога. Это не сертификат доступности и не замена ручной проверке скринридером.
- **Steiger**: границы FSD и публичные API.
- **TypeScript**: strict, noUncheckedIndexedAccess, exactOptionalPropertyTypes; приложение и tooling проверяются отдельно.

```sh
npm run check
npx playwright install
npm run test:e2e
```

E2E сам собирает pre-prod и поднимает preview на 4173, затем останавливает сервер. Тесты рассчитаны на включённый demo-mode и не вызывают сторонний backend.

## Покрытие

Пороги Vitest: 85% statements/lines/functions, 80% branches. Включена вся логика в model, shared/api, env, включая файлы без тестов. Также включены API-адаптеры сущностей. UI покрывается отдельными тестами/E2E; указанное число не означает покрытие всего приложения. Не снижайте пороги ради прохождения CI: тестируйте новые ветки и ошибки.

Отчёты: `coverage/index.html`, `playwright-report/index.html`. Для просмотра E2E: `npx playwright show-report`. Trace можно открыть через `npx playwright show-trace <path>`. Артефакты реальных сценариев могут содержать пользовательские данные; ограничьте доступ и срок хранения.

## Тесты внешнего окружения

`E2E_BASE_URL=https://... npm run test:e2e` отключает локальный webServer. Текущий набор применим только к такой же демо-версии в изолированном окружении. Для настоящего pre-prod создайте отдельные smoke-тесты, тестовую учётную запись и очистку fixtures; не запускайте сценарии записи по prod.

## Добавление тестов

Для model — позитивный сценарий, граничные значения и запрещённые переходы. Для API — некорректный ответ, 401/403/5xx, отмена. Для пользовательского действия — success/error/loading и восстановление. Ищите элементы по роли и доступному имени, не по Tailwind-классам. Новые route-страницы проверяйте прямым переходом и обновлением URL на Nginx.
