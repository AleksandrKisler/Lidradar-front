## Создание и предзаполнение

1. Переиспользовать модалку/валидацию настроек. Один POST создаёт точку;
   до получения исхода повтор и закрытие формы заблокированы.
2. Полученный ID сохранить, точку добавить в список один раз и выбрать.
   Вернуться к её графику с валидной полной стандартной неделей:
   **10:00–19:00 у рабочих дней существующего стартового шаблона**.
   Маска рабочих/выходных дней не меняется. Это отдельный onboarding-default,
   а не изменение шаблона настроек или серверных порогов 45/120.
3. Сразу выполнить существующий PUT семи дней и timezone этой точки.
   До подтверждения инициализация занята; дальнейшие действия заблокированы.
4. После PUT ACK — baseline и «График заполнен». Пользователь может оставить
   default без правок. После отказа PUT — точка/ID/draft сохраняются, общий
   блок ошибки и ручной повтор **только PUT того же ID**. POST не повторяется.

После подтверждённого POST отмена формы не удаляет созданную точку.
Неизвестный исход самого POST — отдельная сверка списка без автоматического
повтора и без доказательства по одному совпадению имени. PUT возможен только
при достоверно известном/выбранном ID. Инициализация default при создании
не означает автосохранение пользовательских правок или переключения точек.

## Модель страницы и состояния

Страница хранит выбранный ID и коллекцию для всех активных точек:
raw-дни/timezone, baseline, ревизию, валидность/ошибки, состояние инициализации
и отдельный исход записи. Существующая полная неделя загружается как
подтверждённая; не заменяется default. Новая неделя сразу валидна, её сетевое
подтверждение учитывается отдельно.

Переключение с неверным пользовательским вводом разрешено без запроса,
подтверждения потери и сброса. Ошибка невыбранной точки остаётся видимой.
«График заполнен неверно» относится к вводу, а не к сети. Прежнее штатное
«График не задан» у новой точки больше не применяется.

Контекст ограничен user/tenant/экземпляром страницы. Refetch не стирает dirty
и неподтверждённые версии; поздние ответы другого контекста игнорируются.
Переименование сохраняет draft, подтверждённый новый timezone используется
в следующем PUT без конверсии местных часов, active меняет состав после PATCH ACK.

После F5/ухода восстанавливаются серверные данные, несохранённые правки не
гарантируются. При открытии шага существующая точка с пустой неделей получает
стандартный draft и действие повторить PUT без POST. Неполный ответ не
достраивается выходными как будто это подтверждённая неделя. Серверный resume
остаётся по ADR 0045: при другой полной неделе он может направить дальше;
автоматический возврат к каждой незавершённой инициализации не обещается.

## Сохранение всех правок и повтор

Весь активный список должен иметь валидные draft и подтверждённую инициализацию.
Неизменённый подтверждённый default не требует PUT повторно. Неподтверждённая
инициализация имеет свой ручной повтор, неверный draft сначала исправляется.

Перед сохранением свежий GET сверяет состав без перезаписи draft; затем
фиксируются контекст, ID, ревизии и payload. Последовательная очередь PUT
останавливается на первом сбое. A ACK/B отказ/C not_sent сохраняют все draft;
повтор пропускает неизменённую A. Никакой повтор графиков не создаёт точек.
Во время команды отключены повтор, ввод/выбор, плюс, карандаш и нижнее «Назад».

Unknown PUT сначала сверяется свежим GET без пятиминутного cache. Сравниваются
семь дней и timezone, без ID строк/порядка/updatedAt. Совпадение подтверждает
состояние; отличие допускает ручной PUT после сверки, недоступный GET не
запускает автоматический повтор. После очереди свежие точки/onboarding
подтверждают переход; сбой финального GET повторяет только чтение.

POST → PUT не атомарны вместе. Существующий PUT атомарен на одну точку,
точный повтор при тех же данных — no-op; защиты от параллельной перезаписи
и exactly-once нет. `401`/`403` останавливают очередь, `404` требует сверки
доступности без пересоздания. Общего rollback/удаления точки после ошибки нет.

## Приёмка и следующий этап

Реализация — только frontend по отдельному поручению. API уже достаточен;
backend-поставка, новый предикат LOCATION и генерация API ради этой US не нужны.
Действующий [RELEASE-SCOPE](../frontend-v2/RELEASE-SCOPE.md) сохраняется,
поставка/версия определяются отдельно.

Unit/browser-проверки: default без ручного заполнения; POST201 → PUT200;
POST201 → PUTfail/unknown → повтор только PUT sameID; unknown POST без дубля;
F5 между командами и прежний resume; invalid A → B → A; refetch/PATCH/context;
частичная очередь, финальный read-retry и регрессия модалок/редактора настроек.

Все AC-01–24 и три адаптива проверяются отдельно от исторической Figma/QA.
После адресных тестов — `npm run check`, `npm run build:pre-prod` и gates
WORKFLOW. План не является TEST/FUNCTIONAL/UI PASS, runtime-тесты сейчас
не запускались. Настройки US-M02-06 сохраняют своё подтверждение потери;
в переключение онбординга оно не переносится.
