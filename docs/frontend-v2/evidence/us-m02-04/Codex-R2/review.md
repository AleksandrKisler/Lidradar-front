## B-01 · Бюджет пока не увеличивать автоматически

| Источник                           |  Total JS |     Лимит |       Critical load |

| Новый замер уже существующего dist | 928 530 B | 905 600 B | 287 349 / 304 800 B |

Текущий перерасход — **22 930 B, около 2,53%**. Собственной production-сборки
Codex не выполнял; разницу 1 B с отчётом не приписываем исходникам R7c.
Лимит суммирует все JS assets: перенос в lazy-чанки не сокращает total JS.

Рекомендация — сначала ограниченный измерительный проход: сопоставимые
production-срезы до/после пакета, поиск дублирования/неиспользуемого кода,
проверка безопасной экономии с сохранением initial-load и всех AC.
Без такого измерения нет подтверждённого кандидата, который уберёт 23 KB,
и нет точного per-story attribution. Прибавка R6→R7c около 2 KB не описывает
весь незакоммиченный пакет. Если безопасной экономии недостаточно — отдельное
решение владельца по новому лимиту с baseline, причиной и запасом.
Текущий отчёт новый бюджет не утверждает.

## UiDialog · Отдельное ограниченное исправление общего компонента

Не считать UiSheetDialog PASS доказательством для UiDialog. Handoff сообщает
аналогичный дефект WebKit, а UiDialog собственного исправления не получил.
Он используется в меню, фильтрах, услугах, подтверждениях и других окнах.

Рекомендация: сначала адресно воспроизвести дефект UiDialog, затем применить
согласованное поведение Tab/Shift/Option+Tab без перехвата Ctrl/Cmd+Tab.
Сохранить Escape, outside-dismiss, initial focus, focus return и nested overlays.
Нужны unit и browser-regressions нескольких характерных потребителей, включая
WebKit; после изменения повторно проверить chunk graph и оба JS-бюджета.
Это frontend-follow-up, без backend и без общего редизайна окон.

## Рекомендации по copy и расхождениям с Figma

Это предлагаемые границы следующего поручения, а не уже выполненные правки.

1. **«Добавить точку»: сохранить текущую доступную кнопку до submit.**
   Пустой submit показывает «Введите название точки.» и не делает POST по
   AC-M02-04-04. Жёсткий disabled не должен молча убрать этот путь валидации.
   Не делать доступную кнопку визуально неотличимой от disabled ради серого
   образца. Busy-блокировка сохраняется.
2. **Имя владельца на phone пока сохранять.** Текущая обязательная проверка
   US-M01-01 T25/G07 требует видимого имени в header на 320/390/834/1440.
   Скрытие имени — отдельное изменение общего header и принятой приёмки M01,
   не локальная полировка шага 2.
3. **Подсказку phone-08 можно адаптировать по макету.** Одна модель ошибки
   и одна валидация не требуют одной строки для всех ширин: desktop может
   показывать «Исправьте время в …», phone — «Исправьте график: …».
   Сохранить название проблемной точки, доступность возврата и aria-связи.
4. **M-1 привести к уже принятой US-M02-02.** В текущем каноне B1/B2/B3
   для обоих полей указаны «От 1 до 1440 минут.» и «Порог — целое число минут.».
   В общей schema отличаются пунктуация и текст второго поля. Это подтверждённое
   расхождение, а не необходимость заново выбирать фразу. Исправление затронет
   onboarding и настройки; нужны адресные проверки ошибок обоих полей и контекстов.
