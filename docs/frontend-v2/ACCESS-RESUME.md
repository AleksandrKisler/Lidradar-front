## Несовпадения прежних stand-fixtures с stage

`tests/e2e/stand/support.ts` ожидает cookie `lidradar_session`, а существующий
Vite stage-proxy специально использует на loopback `lidradar_stage_session`.
Перед реальным QA проверить/адаптировать тестовый helper под stage-контур,
не ослаблять runtime-cookie на backend ради старого assertion.
Профили stand empty/small/large и demo qaN-min/mid/max не считать одинаковыми
без проверки данных; выбрать выделенные тестовые accounts и password file.
Basic Auth прокси и вход пользователя приложения — разные credentials.

Интеграционный helper меняет только основной разработчик в разрешённой фазе
кода. Сейчас это найденная подготовительная зависимость, не выполненное
исправление и не новый frontend-дефект, доказанный прогоном.
Реальные 24 группы не запускать как нагрузочный цикл на одном stage-IP:
REGISTER 5/час и precheck 10/15 минут сохраняются. Ошибки/гонки массово проверять
детерминированными mocks, stage — адресным выделенным интеграционным прогоном.
