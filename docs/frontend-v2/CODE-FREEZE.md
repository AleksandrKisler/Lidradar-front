# Заморозка frontend перед релизом 01.11.2026

Решение владельца от 31.10.2026: после завершения приёмки настроек зафиксировать
текущую версию, отправить её в `stage` и включить автодеплой. Production исключён.

Принятый исходный снимок: commit `ee33540`, settings S6 с TEST/FUNCTIONAL
frontend/mock PASS и desktop UI PASS, manifest
`09cedd0ba730cc8f761c4f72055fb03c884fe63e133398e09a208068419f674d`.
Интеграционный кандидат включает историю `stage` и проверенный механизм
автодеплоя. Финальный RC обозначается отдельным annotated Git tag после gates.

До фактического релиза разрешены только точечные исправления воспроизводимых
дефектов, необходимые проверки, release evidence и сопровождение CI/stage deploy.
Новые функции, крупные изменения интерфейса, API, зависимостей и пересмотр
бюджетов откладываются либо требуют нового явного решения владельца.
[Фиксация макетов](DESIGN-FREEZE.md) продолжает действовать.

Каждое исправление — отдельный commit с issue/причиной, воспроизведением и
затронутыми проверками. Старые RC tags, snapshots, assertions, PNG и логи не
перезаписываются; после изменения кандидата создаётся новый RC tag.
Нельзя ослаблять coverage/budgets/assertions ради прохождения gates.

Порядок: feature/fix → локальная проверка → интеграция в `stage` → обязательный
CI → автоматический stage deploy точного SHA → живой stage QA. Backend остаётся
на текущем deployed commit, миграции автоматически не продвигаются.
`main`, production merge и production deploy требуют отдельного поручения.
См. [настройку автодеплоя](../staging-autodeploy.md).

Tablet/mobile redesign настроек отложен владельцем; это не отменяет регрессии
существующего узкого интерфейса. Sandbox остаётся только localhost/stage.
Frontend/mock PASS не подменяет реальную проверку persistence, email/Telegram
или полного AI pipeline.
