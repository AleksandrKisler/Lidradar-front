## 5. Вопросы, требующие решения (для следующих задач)

**Продукт / поведение**

1. **US-M01-08 шаг 5.** Запоминание последней организации после выхода и входа: либо менять поведение (серверная память выбора), либо править story. Сейчас — не PASS.
2. **«Сохранить компанию».** В макете активна, в story US-M02-05 шаг 3 — неактивна без изменений. Реализована неактивная.
3. **Окно «Уведомления в Telegram».** Реализован автоматический выпуск одноразовой ссылки при открытии (макет показывает активную ссылку сразу). Подтвердить либо вернуть явную кнопку.
4. **Личные уведомления: «Отключить».** В окне макета нет; осталось в карточке на «Интеграциях» и «Настройках». Нужно решение: оставить так или добавить в окно.
5. **Токен бота после отказа.** Реализовано очищение (токен не переживает отправку), в макете точки остаются в поле.
6. **Несколько точек.** В макете нет выбора точки для графика (US-M02-06) — оставлен список «Точка» в карточке графика. Нужен макет или подтверждение.
7. **MAX.** Карточка статична («В работе»): в API нет провайдера MAX.
8. **Telegram Business Mode → Secretary Mode.** Тексты шагов из макета; подтвердить актуальность терминологии с продуктом.

**Дизайн / макеты** 9. **Дизайн настроек не утверждён формально** (`design-index.json`: `otherAreas`, «готово к согласованию»). Решение владельца «начать S5» принято как допуск; для F06 нужно закрепить статус «approved». 10. **Оболочка.** В кадрах настроек боковая колонка отличается от утверждённой оболочки Radar («Источник Telegram», «1 точка · Москва», без «Выйти»). Какая — канон? 11. **Кадры Figma, расходящиеся между устройствами:** тексты «Всё подключено» (desktop и tablet/phone), «Применить ко всем рабочим дням» (phone) и «Скопировать часы первого рабочего дня» (desktop/tablet), галочка шага 4. 12. **Состояния без макета** (собраны из примитивов): «Пароль изменён при сессии», «Вы в команде», создание первой точки, пустой каталог услуг и сбой загрузки, состояния страницы настроек на tablet/phone, окна tablet без подложки.

**Техническое** 13. **Бюджет JS 99,3 %.** Дальше F04–F06 будут требовать новых поднятий. Решение: либо планово оптимизировать (разбивка по маршрутам, удаление дублей `UiDialog`/`UiSheetDialog`, вынос текстов инструкции), либо задать бюджет на этап. 14. **Скриншоты инструкции (≈2,2 МБ) лежат в `src`.** Подтвердить источник, обезличивание и актуальность версии Telegram; решить, где их хранить (репозиторий / CDN). 15. **Две системы диалогов** (`UiDialog` и новый `UiSheetDialog`) — унифицировать при F06. 16. **Коммиты.** S4d, S4e, S5 не закоммичены; нужна команда на коммит (и разбивка на коммиты по этапам).

## 9. Процесс: что повторялось и как снизить риск

- Каждый этап проходил 1–3 круга ревью (visual + functional); визуальное ревью почти всегда возвращало FAIL по отступам и типографике, функциональное — по гонкам, утечкам слушателей, фокусу. **Правки после последнего круга агентами не пересматривались** (записано в STATUS по каждому этапу).
- Типичные причины возвратов: повторный запрос/таймеры после закрытия окна; потеря ввода при смене контекста; нативный `disabled`; контраст бейджей; несовпадение высот кадров при снимке полной страницы.
- Рекомендации: добавить в харнес снимок «видимого экрана» для окон; хранить эталоны всех трёх устройств для состояний до начала этапа; фиксировать в задаче этапа список «без макета» заранее.
